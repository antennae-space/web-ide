# Debug plugin

The debug host: a client of the [Debug Adapter Protocol](../../docs/design/debug.md) in the pod, which runs the debug sessions of a project and relays their events to its windows. It provides the `debug` capability. A built-in plugin: [plugins.md](../../docs/design/plugins.md); `plugin.json` is its manifest.

- **Pod** (`*.go`, package `debug`): the sessions are `internal/dap`, a part of the runtime of the project (`rt.Part("debug")`) — started adapters, stopped with the project, not on idle. `config.go` reads `.ide/debug.json` of the main project (the configurations, `${workspaceFolder}`, `${file}`, `${fileDirname}`, `${env:NAME}` replaced) and `breakpoints.go` `.ide/breakpoints.json` of the worktree. The adapters themselves are the language packs' (`contributes.debuggers`); the core runs them on their grant `debugger:<type>` (`server/plugins_debuggers.go`).
- **Methods**: `debug.debuggers` (the adapters of the packs, where each is, the languages they debug), `debug.configurations` (the file's configurations, the packs' templates and the path of the file), `debug.addConfiguration`, `debug.templates`, `debug.start`, `debug.stop`, `debug.restart`, `debug.sessions`, `debug.threads`, `debug.stack`, `debug.scopes`, `debug.variables`, `debug.evaluate`, `debug.continue`, `debug.pause`, `debug.next`, `debug.stepIn`, `debug.stepOut`, `debug.breakpoints`, `debug.setBreakpoints`, `debug.install`. A `runInTerminal` of an adapter opens a console of the Console tool.
- **Events**: `debug.session` (a session appeared, changed, ended; `running` from the request of a step on), `debug.breakpoints` (a file's breakpoints saved by a window), `debug.verified` (which breakpoints of a file the adapter set, and why not the others), `debug.stopped` (the thread, the reason, the file and the line), `debug.output`, `debug.breakpoint`, `debug.thread`, `debug.event`. The variables stay lazy: a row asks for its `variablesReference`.
- **Page** (`web/`, the chunk `plugin-debug`, #189): `state.ts` (the sessions of the worktree shown and what the tool shows of each, lazy), `DebugTool.tsx` (the tabs of the sessions, the run buttons of the corner), `frames.tsx` (Threads & Variables), `console.tsx`, `run.ts` (Run › Debug…, the templates, *Edit configurations…*), `gutter.ts` (the breakpoints and the execution line through `editorDecorations`), `focus.ts` (the tool on the first stop, the notification of a hidden window, the tool closed at the end). Its settings: `show_on_stop`, `keep_open_at_end`. The commands and their keys are in `plugin.json`; the core's menu bar shows them in **Run**.
- **Push**: a stop sends the notification of the kind `debug` (`pod/push`) to the devices that show no window.
- **E2e** (`e2e/`, run by `e2e/run.sh`; the lang-go pack and the `dlv` check in `plugins/debug/e2e/lib/langgo.cjs`): debugtool (the gutter, Run › Debug… and its templates, the tool focused on the stop, a frame, a struct expanded, F8, the console, Stop closing the tool, the breakpoint saved at its moved line), debug (the lang-go pack with `debugger:go`, a Go program stopped on a line breakpoint by `dlv dap`, its stack and a local read through the methods; skipped when `dlv` is not installed).

The Go package imports the core of `pod/`; its texts are in `i18n/<lang>.json`, added in `init` (`i18n.go`).
